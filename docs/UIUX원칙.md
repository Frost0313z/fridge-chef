# UI·UX 원칙

현재 화면을 수정할 때 지켜야 할 기준입니다. 변경 과정과 완료 이력은 Git에서 관리합니다.

## A. 정보 구조

### A1. 한 화면에 하나의 주 행동

페이지 제목 아래에서 사용자가 가장 먼저 해야 할 행동을 분명히 보이게 합니다. 보조 행동은 같은 시각적 무게를 갖지 않습니다.

### A2. 상단·본문·하단 구분

라이트와 다크 모드 모두에서 상단 바, 본문, 하단 내비게이션의 배경이나 경계가 구분되어야 합니다. 색은 토큰으로 관리합니다.

### A3. 카드의 역할

카드는 독립된 정보 묶음이나 상하 관계를 설명할 때만 사용합니다. 같은 모양의 중첩 카드를 반복하지 않습니다.

### A4. 냉장고의 예속 구조

기본 재료는 “지금 들어있는 재료” 안에 둡니다. 별도 배경 카드와 제목으로 구분하고 접고 펼칠 수 있게 하되 독립 메뉴처럼 보이지 않게 합니다.

### A5. 모바일 내비게이션

모바일은 고정 하단 내비게이션을 사용합니다. 냉장고 바로가기는 작은 플로팅 버튼으로 분리하며 내비게이션, 안전 영역, 주요 버튼을 가리지 않아야 합니다.

## B. 상호작용

### B1. 상태를 즉시 보여 주기

클릭 후 로딩, 성공, 오류 중 무엇이 일어나는지 같은 영역에서 알려 줍니다. 오래 걸리는 작업은 중복 실행을 막습니다.

### B2. 냉장고 현황은 간단하게

하단 냉장고 바로가기는 상세 재료명을 나열하지 않고 “냉장고 현황”처럼 짧게 표시합니다. 세부 내용은 냉장고 화면에서 확인합니다.

### B3. 파괴적 행동

전체 삭제나 덮어쓰기는 대상과 결과를 알리고 확인을 받습니다. 한 항목 삭제처럼 복구 가능한 행동은 실행 후 되돌리기를 우선합니다.

### B4. 사용자가 최종 결정

사진 분석과 추천 결과는 후보입니다. 냉장고 저장, 요리 완료, 식단 반영처럼 상태가 바뀌는 순간에는 사용자가 선택을 확인해야 합니다.

### B5. 빈 상태와 오류

문제와 다음 행동을 함께 제시합니다. 상태 코드와 내부 데이터 이름은 사용자 문구에 노출하지 않습니다.

## C. 반응형과 접근성

### C1. 모바일 우선

작은 화면에서 가로 스크롤 없이 핵심 흐름을 완료해야 합니다. 고정 요소가 콘텐츠와 겹치지 않도록 하단 여백과 안전 영역을 반영합니다.

### C2. 터치와 키보드

- 터치 대상은 충분한 크기와 간격을 둡니다.
- 모든 기능은 키보드로 접근할 수 있어야 합니다.
- 포커스 표시를 제거하지 않습니다.
- 아이콘만 있는 버튼에는 접근 가능한 이름을 제공합니다.

### C3. 대비

본문, 보조 문구, 경계선, 비활성 상태는 두 테마에서 구분되어야 합니다. 색만으로 완료·오류·선택 상태를 전달하지 않습니다.

### C4. 모달과 접이식 영역

모달은 제목과 닫기 수단이 분명해야 하며 배경 조작을 막습니다. 접이식 영역은 펼침 상태를 보조 기술에도 전달합니다.

### C5. 움직임

전환은 상태 변화를 이해시키는 범위에서 짧게 사용합니다. 움직임 줄이기 설정을 존중합니다.

## D. 화면 변경 점검표

- 모바일과 데스크톱에서 잘림이나 겹침이 없는가?
- 두 테마에서 영역과 텍스트가 구분되는가?
- 키보드 포커스와 버튼 이름이 올바른가?
- 로딩·빈 상태·오류·성공 상태가 있는가?
- 고정 요소가 콘텐츠를 가리지 않는가?
- 문구가 다음 행동을 알려 주는가?
