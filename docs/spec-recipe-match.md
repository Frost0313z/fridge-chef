# 실제 레시피 매칭 명세

## 목적

사용자가 가진 재료와 실제 레시피 데이터를 먼저 대조해 근거 있는 추천을 제공합니다. 적합한 결과가 없을 때만 인공지능 생성 결과로 보완합니다.

## 데이터 출처와 경계

- 출처: KADX 만개의레시피 데이터
- 라이선스: CC BY-NC-ND
- 원문: https://www.kadx.co.kr/opmk/frn/pmumkproductDetail/PMU_6bcd8bf8-50f0-4c22-a2cb-100a5a8a6629/5
- 레시피 링크: https://www.10000recipe.com/recipe/{id}

반드시 지킬 사항:

- 출처를 표시하고 비상업적 범위에서만 사용한다.
- 원문의 소개글, 변형한 제목, 조리 순서를 복제하거나 재배포하지 않는다.
- 재료명, 시간, 인분, 분류 같은 사실 정보와 원문 링크만 사용한다.
- 실제 데이터 카드의 조리 순서는 비워 두고 원문으로 연결한다.
- 원본 CSV와 생성 인덱스는 공개 Git에 올리지 않는다.

상업화 전에는 별도 허가나 대체 데이터가 필요합니다.

## 인덱스 생성

    python scripts/build_recipe_index.py

- CSV의 CP949 인코딩을 고려한다.
- 결과는 api/recipes_index.json이며 형식 버전은 3이다.
- 압축 키는 v, n, a, p, t, b, c, r을 사용한다.
- 생성기와 서버의 형식 버전은 함께 바꾼다.
- 파일이 없거나 손상되거나 버전이 다르면 인공지능 추천으로 폴백한다.

## 매칭 규칙

1. 사용자 재료를 정규화한다.
2. 역색인으로 관련 후보만 찾는다.
3. 재료가 3개 미만인 레시피는 제외한다.
4. 가진 재료 비율이 70% 이상인 후보만 남긴다.
5. (보유 수 / 전체 수) × 보유 수 점수로 정렬한다.
6. 같은 요리의 중복을 제거한다.
7. 선택한 분량과 가까운 인분을 우선한다.

모드별 약속:

- “지금 바로 만들기”: 부족한 재료가 없는 결과만 제공한다.
- “조금만 장보기”: 부족한 재료가 적은 결과를 우선한다.

## 배포와 점검

GitHub에는 인덱스가 없으므로 다음 명령을 사용합니다.

    bash scripts/deploy.sh

배포 후 인덱스 검사 통과, 실제 데이터 출처, 원문 링크, 인덱스 누락 시 폴백과 로그를 확인합니다.

## 테스트

    python api/test_handlers.py

완전 보유, 70% 경계, 재료 3개 미만, 중복 제거, 분량 우선순위, 인덱스 누락·손상·버전 불일치를 검증합니다.
