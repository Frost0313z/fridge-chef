- 문서 기준: 현재 구현과 검증할 사업 가설을 분리해 기록

## ① 고객군

### 핵심 고객

- 혼자 살며 일주일에 한 번 이상 직접 요리하는 사람
- 냉장고에 있는 재료를 자주 잊거나 소비기한을 놓치는 사람
- 식비를 줄이고 싶지만 매번 식단을 계획하기는 부담스러운 사람
- 복잡한 재고 관리보다 빠른 추천과 간단한 기록을 원하는 사람

### 얼리어답터

> 요리할 의지는 있지만 “오늘 무엇을 먹을지” 결정하는 과정이 귀찮아 배달이나 즉석식품으로 타협하는 자취생

기획자 본인이 이 문제를 직접 겪는 첫 사용자입니다. 다만 개인 경험만으로 전체 고객을 대표한다고 가정하지 않고 실제 사용성 검증이 필요합니다.

### 이번 범위에서 제외한 고객

- 가족 구성원별 계정과 실시간 동기화가 필요한 다인 가구
- 정밀한 중량·수량 기반 재고 관리가 필요한 사용자
- 조리보다 완제품 주문 자체가 목적인 사용자
- 스마트폰이나 웹 입력에 큰 부담을 느끼는 사용자

## ② 문제

### 핵심 문제 3가지

| 문제 | 사용자가 겪는 상황 | 결과 |
| --- | --- | --- |
| 냉장고 파악이 어렵다 | 어떤 재료가 있고 언제 넣었는지 기억하지 못함 | 재료 방치와 중복 구매 |
| 메뉴 결정이 어렵다 | 가진 재료로 무엇을 만들 수 있는지 바로 떠오르지 않음 | 요리 시작을 미루고 배달로 전환 |
| 식단과 장보기가 분리된다 | 계획한 메뉴와 실제 냉장고 상태가 연결되지 않음 | 필요 없는 재료를 사거나 필요한 재료를 빠뜨림 |

### 근본 원인

문제는 요리 의지가 없는 것이 아니라 행동까지 가는 과정의 마찰이 크다는 점입니다.

    재료 기억 → 메뉴 검색 → 가능 여부 판단 → 식단 구성 → 장보기 정리

이 과정을 매번 사용자가 머릿속으로 처리해야 하므로, 한 단계만 막혀도 “오늘은 그냥 시켜 먹자”로 돌아가기 쉽습니다.

### 기존 대안

| 대안 | 장점 | 남는 문제 |
| --- | --- | --- |
| 배달 앱 | 가장 빠르게 한 끼를 해결 | 식비가 늘고 냉장고 재료는 계속 남음 |
| 레시피 검색 | 많은 조리 정보를 제공 | 요리명을 알아야 검색하기 쉬움 |
| 메모·스프레드시트 | 자유롭게 기록 가능 | 추천·식단·장보기와 자동 연결되지 않음 |
| 장보기 앱 | 구매 목록 관리에 편리 | 이미 가진 재료와 먹은 재료를 함께 반영하기 어려움 |
| 스마트 냉장고 | 재고 관리 자동화 가능 | 가격과 접근성 부담, 인식 결과 확인 필요 |
| 머릿속 기억 | 별도 입력이 없음 | 재료가 많아질수록 정확도가 빠르게 낮아짐 |

## ③ 고유의 가치 제안

> ## 냉장고에 있는 대로, 오늘 한 끼 완성

### 한 문장 설명

냉장고 재료를 한 번 기록하면, 지금 만들 요리부터 다음 장보기까지 같은 정보로 이어집니다.

### 사용자가 얻는 가치

- **결정 시간 단축:** 가진 재료로 가능한 결과를 먼저 확인
- **낭비 감소:** 냉장고 재료와 기본 양념의 실제 보유 여부 반영
- **장보기 단순화:** 식단에 부족한 재료만 한 목록으로 통합
- **행동의 연결:** 요리 완료가 냉장고·식단·절약 현황에 함께 반영
- **과장 없는 안내:** 인공지능 결과는 후보로 제공하고 최종 결정은 사용자가 수행

### 하이컨셉

> 비싼 스마트 냉장고 없이, 지금 쓰는 냉장고를 조금 더 똑똑하게 사용하는 방법

### 핵심 설계 원칙

냉장고를 서비스의 **단일 기준 정보**로 사용합니다.

    장보기 완료 ──→ 냉장고에 추가
                      ↓
    요리 추천 ←── 현재 보유 재료 ──→ 식단
                      ↓
                요리 완료 후 차감
                      ↓
             남은 식단의 장보기 재계산

## ⑨ 경쟁 우위

### 현재 가진 강점

- 기획자 본인이 핵심 문제를 지속적으로 겪는 첫 사용자
- 냉장고를 추천·식단·장보기·요리 완료가 함께 쓰는 단일 정보로 설계
- 실제 레시피를 먼저 검색하고 부족할 때만 인공지능으로 보완
- 구매와 소비를 양방향으로 반영해 오래 쓸수록 상태가 실제 냉장고에 가까워지는 구조
- 프레임워크 없이 전체 요청 흐름을 이해하고 수정할 수 있는 단순한 기술 구조

### 아직 경쟁 우위라고 보기 어려운 부분

- 기능은 다른 서비스가 복제할 수 있습니다.
- 사용자 기반과 네트워크 효과가 없습니다.
- 개인 데이터가 브라우저에만 있어 기기를 바꾸면 전환 비용도 사라집니다.
- 독점 레시피나 영양 데이터가 없습니다.

따라서 현재의 경쟁 우위는 완성된 방어벽이 아니라 **사용 흐름의 연결성과 문제 이해도**에 가깝습니다.

| 4 | 식단·장보기가 함께 쓰이는가 | 기능별 사용 흐름 관찰 | 식단 생성 후 장보기 이동 |

| 6 | 채널별 유입 차이를 측정할 수 있는가 | 개인정보를 최소화한 분석 도입 | 유입→추천 퍼널 확인 |

## 지금 내릴 수 있는 결론

### 확인된 사실

- 5개 화면과 메뉴 이동이 구현되어 있습니다.
- 추천·식단·사진 분석에 인공지능 API를 사용합니다.
- 실제 레시피 검색, 냉장고, 식단, 장보기, 요리 완료가 연결되어 있습니다.
- 모바일 반응형과 다크 모드를 제공합니다.

### 아직 확인되지 않은 것

- 실제 사용자가 꾸준히 재방문하는지
- 식비 절약 효과가 어느 정도인지
- 어떤 유입 채널이 효과적인지
- 사용자가 기기 동기화나 고급 기능에 비용을 지불할지

린 캔버스는 완성된 사업 계획서가 아니라 **가장 위험한 가설을 빠르게 찾고 검증하기 위한 문서**입니다. 기능이 늘어날 때보다 사용자 증거가 생길 때 우선 갱신합니다.
